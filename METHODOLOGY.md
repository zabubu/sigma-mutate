# Methodology

This document describes how sigma-mutate measures the robustness of Sigma rules, what each
number in [RESULTS.md](RESULTS.md) means, and where the method stops.

## Pipeline

For every rule in a folder (here SigmaHQ `rules/windows/process_creation`):

1. **Build a matching event.** SigmaHQ rules ship without sample logs, so `synth.py` derives a
   minimal true-positive event from the rule: it picks a set of selections that makes the
   condition true, picks one value per constrained field, gives `Field: null` filters a dummy
   value so they don't fire, prefixes the command line with the program name when the rule
   names one, and checks the result with the matcher. Only *minimal* selection sets are kept:
   with both sides of `A or B` true, an evasion of A would be hidden by B.
2. **Rewrite the command line.** `mutators.py` produces variants of `CommandLine` that should
   behave exactly like the original (see below).
3. **Replay.** Each variant is evaluated against the rule. A variant that is no longer detected
   is an evasion.
4. **Cross-check** (`--verify-rsigma`). The original event and every variant are also evaluated
   by [rsigma](https://github.com/timescale/rsigma), an independent Sigma engine. Any
   disagreement is reported.

## Rewrites (mutators)

| Mutator | Example | Assumption |
|---|---|---|
| `quote_split` | `h""ttp` | argv for arguments, cmd.exe for the program name |
| `quote_wrap` | `"-urlcache"` | argv |
| `space_padding` | two spaces between arguments | argv |
| `tab_separator` | tabs instead of spaces | argv |
| `caret_insert` | `h^ttp` | cmd.exe |
| `option_prefix_swap` | `/urlcache` for `-urlcache` | program |

Quote and caret insertions are made at three spots per token (first, middle, last), and also
in every argument at once, since a rule pattern can span several tokens. They are never placed
next to a backslash (`\"` means something else to the argument parser), a quote, whitespace or
a cmd.exe metacharacter.

Each variant carries the assumption it relies on:

- **argv**: same result after standard Windows argument parsing (`CommandLineToArgvW`, used by
  the C runtime and most programs). This is the only assumption used for the headline numbers.
- **cmd.exe**: only true when the command line is interpreted by cmd.exe (carets, quotes in the
  program name).
- **program**: depends on the program (accepting `/x` as well as `-x`, or a known exception
  below).

## Validation on Windows

`scripts/validate_mutators.py` runs harmless, read-only commands and all their variants on a
real Windows 10 host, and compares exit code and output with the original. The 15 commands
cover certutil, whoami, reg, findstr, sort, `cmd /c type`, powershell, curl, where, schtasks,
net, netsh, sc, bitsadmin and wmic. Results are in `validation.csv` and summarised in
RESULTS.md. Summary of the last run:

- Every argv variant generated by default behaved like the original: 193/193.
- cmd.exe variants worked through cmd.exe (182/182, one launch blocked by the antivirus), and
  program-name variants never worked without it (0/90), which confirms that assumption.
- Counter-examples, all filed under `program` so they never count by default:
  - `net.exe` and `wmic.exe` do not treat a tab as a separator;
  - `wmic.exe` keeps quotes inside a word (`o""s` is not `os`);
  - `cmd.exe` parses its own command line: `cmd /c t""ype file` fails and `/""c` is not `/c`.

The script runs commands from a temporary folder with a relative file name, so the CSV holds no
local path. It must be launched from a normal Windows shell: from Git Bash, `cmd.exe` would find
Git's own `curl`, `sort` and `whoami` first in the PATH and the comparison would be meaningless.

Programs with a clean validation run are listed in `VALIDATED_PROGRAMS`; rules about them form
the "program validated on Windows" scope in RESULTS.md. `schtasks.exe` gave unstable output in
an earlier run and is not counted as validated yet.

## Verdicts

Per rule, using argv variants only:

- **evadable**: at least one variant is not detected;
- **resistant**: at least 3 non-whitespace variants, all detected. This only means the rule
  survived these mutators (often because its patterns are punctuation or very short tokens that
  quote insertion cannot touch), not that it is robust;
- **inconclusive**: fewer than 3 meaningful variants applied.

Rules are also split by detection path. A rule flagged `other_paths` can fire without looking at
the command line (for example on the binary name alone). Evading the command line does not evade
such a rule, so RESULTS.md reports a scope that excludes them.

## Sigma support

The matcher (`matcher.py`) handles what the process_creation rules use:

- modifiers `contains`, `startswith`, `endswith`, `all`, `windash`, `re` (with `i`, `m`, `s`),
  `base64` and `base64offset`;
- wildcards `*` and `?` and the Sigma escapes `\\`, `\*`, `\?`;
- `null` values, lists of maps, and conditions with `and`, `or`, `not`, parentheses,
  `1 of x*`, `all of x*` and `all of them`.

Regular expressions are case-sensitive unless `|i` or `(?i)` is used, as in the Sigma
specification, and run with Python's `re`. To build an event for a `re` rule, `regex_sample.py`
walks the regex syntax tree produced by Python's parser and takes the cheapest path (first
branch, minimum repetitions, first acceptable character of a class); the result is checked
against the regex. `base64offset` follows pySigma: three encodings of the value, one per
alignment, with the characters that depend on neighbouring bytes cut off.

Anything else raises an explicit error and the rule is reported as `unsupported` instead of
being guessed. Remaining gaps: `fieldref` (1 rule), keyword (field-less) selections, `null`
inside a value list, and conditions where no small set of selections is enough (3 rules).
Aggregations and `timeframe` are not relevant for process_creation.

The matcher is checked against rsigma on the whole corpus, events and variants included.

## Upstream findings

Running the corpus also surfaces rule bugs. In the SigmaHQ snapshot used for RESULTS.md,
*COM Object Execution via Xwizard.EXE* required `CommandLine` to equal `RunWizard` and, in the
same selection, to contain a GUID. Both cannot be true, so the rule never fired
(`synthesized event does not satisfy the rule`). SigmaHQ fixed that in #6546, but the fix used
`Image|endswith: '/xwizard.exe'` with a forward slash, so the rule still cannot fire on sources
without `OriginalFileName`. Proposed fix:
[SigmaHQ/sigma#6562](https://github.com/SigmaHQ/sigma/pull/6562).

## Limits

- Only `CommandLine` is rewritten. Paths (`Image`), parent command lines and other fields are not.
- Sample events are minimal. A real attack command carries more text, which can only add
  patterns for the rule to miss or catch; the measurement is about the rule's own patterns.
- Variants are validated for the 15 programs above. For other programs the argv assumption holds
  for most binaries built with the Microsoft C runtime but not all (`rundll32`, `msiexec`,
  `mshta`, `wscript`, `cscript` and `regsvr32` still need checking).
- An evasion is a *detection* gap for this rule, not proof that no other rule or product would
  catch the attack.

## Code map

| Path | Role |
|---|---|
| `src/sigma_mutate/matcher.py` | Sigma matcher |
| `src/sigma_mutate/synth.py` | builds a true-positive event from a rule |
| `src/sigma_mutate/regex_sample.py` | builds a string matching a regex |
| `src/sigma_mutate/mutators.py` | command-line rewrites and their assumptions |
| `src/sigma_mutate/scoring.py` | replays variants against a rule |
| `src/sigma_mutate/reference.py` | rsigma wrapper |
| `scripts/corpus.py` | runs a whole rule folder, writes `verif.csv` |
| `scripts/validate_mutators.py` | Windows validation, writes `validation.csv` |
| `scripts/report.py` | writes RESULTS.md from the two CSV files |
| `scripts/crosscheck.py`, `scripts/explain.py` | debugging one rule |

## Related work

Academic work has looked at Sigma rule evasion (e.g. arXiv:2311.10197), and other open-source
tools explore command-line obfuscation. This project focuses on a reproducible, large-scale
measurement with validated equivalence and an independent engine cross-check.
